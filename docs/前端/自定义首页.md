# 自定义首页

`/` 是 Pipker Framework 的公开首页，不要求登录。首页模块将框架提供的默认首页与当前业务系统的专属首页分开维护：框架基线可以持续演进，业务项目也能在不改动路由守卫、登录流程或数据库 RBAC 的前提下替换对外入口。

## 目录结构

```text
frontend/src/modules/home/
├── index.vue
├── api/
│   └── config.ts
└── pages/
    ├── defaults/
    │   ├── index.vue
    │   └── components/
    └── custom/
        └── index.vue
```

| 位置 | 职责 | 是否建议直接修改 |
| --- | --- | --- |
| `src/modules/home/index.vue` | 根首页选择器；读取配置、加载页面，并统一计算控制台入口。 | 通常不修改。只有选择规则或控制台跳转规则变化时才修改。 |
| `src/modules/home/api/config.ts` | 首页变体的唯一源码配置。 | 是。切换默认页与定制页只改此文件。 |
| `src/modules/home/pages/defaults/` | 框架默认公开首页及其拆分区块。 | 框架维护范围，可作为新项目的结构和设计基线。 |
| `src/modules/home/pages/custom/` | 当前业务系统的专属公开首页。 | 是。项目品牌、文案、展示内容和专属交互放在这里。 |

`api/` 当前只放首页变体选择配置，不放页面组件、样式、会话逻辑或业务接口封装。所有首页页面实现统一放在 `pages/` 下。

## 切换默认首页与定制首页

打开 [config.ts](../../frontend/src/modules/home/api/config.ts)，修改唯一配置：

```ts
export const isCustomHomeEnabled = true
```

| 配置值 | `/` 渲染的页面 | 适用场景 |
| --- | --- | --- |
| `false` | `src/modules/home/pages/defaults/index.vue` | 使用框架提供的公开首页。 |
| `true` | `src/modules/home/pages/custom/index.vue` | 使用当前业务系统的专属首页。 |

当前工作区的配置值为 `true`，因此根路径会渲染定制首页。若需要恢复框架默认首页，只需改为 `false`。

该开关是构建期源码配置，不使用环境变量、后端字段或 `localStorage`。切换后路由地址始终为 `/`：不会增加公开路由、不会重定向，也不会向浏览器历史写入额外记录。

开发环境通常会由 Vite 热更新当前页面；生产部署前需要重新构建前端：

```bash
cd frontend
npm run build
```

## 定制首页的最小流程

1. 在 `src/modules/home/api/config.ts` 将 `isCustomHomeEnabled` 设为 `true`。
2. 编辑 `src/modules/home/pages/custom/index.vue`。
3. 保留页面传入的 `consoleActionCopy` 与 `consoleDestination`，继续使用 `RouterLink` 渲染“进入控制台”入口。
4. 访问 `/`，确认地址仍是根路径且显示业务定制内容。
5. 执行构建和空白检查。

```bash
cd frontend
npm run build
git diff --check
```

初始定制页是一个可访问的最小骨架，已有主题切换器、控制台入口和维护提示。项目需要增加内容时可直接编辑 `pages/custom/index.vue`；页面复杂后，建议在 `pages/custom/components/` 下拆分展示区块，而不是将全部内容堆入入口文件。

## 必须保留的页面契约

根首页选择器会向默认页和定制页传入相同的两个 props：

```ts
interface HomePageProps {
  consoleActionCopy: string
  consoleDestination: RouteLocationRaw
}
```

| Prop | 含义 |
| --- | --- |
| `consoleActionCopy` | 无会话时为“进入控制台”；已恢复有效会话时为“进入我的控制台”。 |
| `consoleDestination` | 无会话时为登录路由；有效会话时为当前账户第一个已授权的动态页面；没有可用动态页面时回退到应用壳。 |

如果替换 `pages/custom/index.vue` 的整个页面，必须继续声明并消费这两个 props。不要在定制页中自行读取 token、访问 `localStorage` 或复制登录态判断逻辑，否则默认页与定制页会产生不一致的跳转行为。

## 与登录、RBAC 和动态路由的关系

首页只提供公开介绍和控制台入口，不注册业务菜单，也不绕过现有鉴权机制。

```text
访问 / ──无会话──→ /login
   │
   └──有效会话──→ /api/auth/me 返回菜单中的第一个已授权页面
```

登录后的业务路由仍由 `/api/auth/me` 返回的数据库菜单树决定。只有包含有效 `MENU`、`path`、`routeName` 与 `componentKey` 的页面菜单才会注册为动态路由。定制首页不会让未授权用户访问 `/system/roles`、`/system/routes` 或其他业务页面。

## 样式与主题约束

默认页和定制页都必须使用现有 Sass 设计系统，而不是新增页面级颜色体系。

- 使用 `var(--color-*)`、`var(--radius-*)`、`var(--shadow-*)` 等语义 token。
- Claude 是单色暖白 / 墨黑体系；Element 使用 Element 蓝色后台体系。不要为两个主题复制多套页面颜色。
- 常规控件和面板只使用低圆角：`--radius-small`（4px）、`--radius-control`（6px）、`--radius-panel`（8px）。只有标签和徽标可用 `--radius-pill`；状态点和图形装饰可用 `50%`。
- 不引入 Google Fonts、外部图片、参考站资源或新的图标依赖。
- 页面样式使用 `lang="scss"`，可直接使用全局注入的断点 mixin，例如 `@include at-most('phone')`。
- 为 `320px` 窄屏保留单列布局，并遵从全局 `prefers-reduced-motion` 的静态回退。

默认首页使用 CSS 构建运行时预览，不依赖外部截图。业务定制页也应优先复用主题 token 和 CSS 结构，而不是复制第三方站点的品牌、文案或视觉素材。

## 维护边界

| 需求 | 应修改的位置 |
| --- | --- |
| 切换默认页或定制页 | `src/modules/home/api/config.ts` |
| 修改框架默认首页内容 | `src/modules/home/pages/defaults/` |
| 修改当前系统的对外首页 | `src/modules/home/pages/custom/` |
| 修改首页选择方式或控制台跳转规则 | `src/modules/home/index.vue` |
| 修改公开首页路由与匿名访问规则 | `src/router/index.ts` |

除非首页选择机制本身需要改变，否则不要为了业务首页定制修改 `src/router/index.ts`。同样，不要通过新增静态业务路由替代数据库菜单路由；业务页面仍应遵守现有 `componentKey` 与 RBAC 菜单配置规则。
